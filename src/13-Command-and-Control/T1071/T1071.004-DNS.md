# DNS (T1071.004)

## 一句话通俗理解

> **DNS就是用 DNS 查询和响应传数据。**

## 30秒速查卡

| 维度 | 你需要知道的 |
|------|-------------|
| 这是什么？ | 攻击者把C2指令编码在DNS查询的子域名或TXT记录中，通过DNS协议传输数据，防火墙几乎不会拦截DNS流量 |
| 为什么危险？ | DNS是网络基础设施，任何主机都要做DNS解析，封掉DNS等于断网，安全设备对DNS内容检查力度很低 |
| 谁需要关心？ | DNS管理员、网络安架构师、SOC分析师 |
| 你的第一步防御 | 部署DNS流量监控，检测异常长的子域名查询和高频TXT记录请求 |
| 如果只做一件事 | 统计每台主机的DNS查询量基线，重点关注单主机每日DNS查询超过5000次的异常情况 |

## 技术描述

**通俗解释：**

**过渡段：** 不要误以为C2只是'恶意软件发心跳包'——现代C2基础设施堪比小型互联网公司。攻击者使用CDN隐藏真实服务器、用Domain Fronting伪装流量目的地、借助合法云服务（如GitHub Issues、Slack API）作为通信通道。攻击者的C2流量与正常流量混杂在一起，传统IoC检测几乎无效。
用 DNS 查询和响应传数据，防火墙很难拦截

> 📨 **打个比方**：就像在公司内部的邮件系统里偷偷传递消息——攻击者使用DNS作为通信渠道，因为DNS流量几乎不会被封锁。

**技术原理：**
T1071.004 是 应用层协议（T1071）的子技术，专注于DNS这一特定方面。攻击者在命令与控制阶段，通过DNS来获取目标系统或组织的相关信息，为后续攻击步骤做准备。

**用途与影响：**
- 为后续攻击提供关键信息支撑
- 提高攻击的成功率和精准度
- 降低攻击被发现的概率

## 真实攻击流程

### 典型场景

攻击者在 **命令与控制** 阶段使用 DNS协议 技术，以下是典型的攻击步骤：

```mermaid
graph TD
    A["在被黑系统植入DNS木马"] --> B["木马构造DNS查询请求"]
    B --> C["DNS查询中编码C2指令"]
    C --> D["攻击者DNS服务器返回响应"]
    D --> E["响应中解码执行指令"]
    style C fill:#ff6b6b,stroke:#333,stroke-width:2px
```

**步骤详解：**

1. **在被黑系统植入DNS木马** - 部署支持DNS隧道通信的恶意载荷到目标系统
2. **木马构造DNS查询请求** - 将C2指令数据编码为子域名格式发起DNS查询（关键步骤）
3. **DNS查询中编码C2指令** - 通过TXT记录或A记录查询将指令数据嵌入DNS查询包
4. **攻击者DNS服务器返回响应** - 控制的DNS服务器解析查询并返回包含响应数据的DNS应答
5. **响应中解码执行指令** - 从DNS响应的记录数据中解码并执行攻击指令

5. **利用信息进行下一步攻击** - 基于收集到的信息制定后续攻击计划

## 攻击流程

```mermaid
graph LR
    A[注册攻击者控制的权威DNS域名] --> B[植入支持DNS隧道的木马后门]
    B --> C[木马将C2数据编码为长子域名发起TXT查询]
    C --> D[权威DNS服务器返回加密TXT记录响应]
    D --> E[木马解码TXT记录执行指令并回传结果]
    
    style A fill:#4a90e2
    style E fill:#ff6b6b
```

**关键步骤说明：**

1. **注册攻击者控制的权威DNS域名**: 攻击者在Namecheap/GoDaddy注册一个看起来无害的域名（如`cdn-update-services[.]com`），将其NS记录指向攻击者控制的权威DNS服务器（如dnscat2、dns2tcp服务端），确保该域下所有子域查询都会被路由到攻击者的服务器
2. **植入支持DNS隧道的木马后门**: 通过钓鱼或漏洞利用在目标主机部署支持DNS协议的后门（如SUNBURST、Cobalt Strike DNS Beacon、dnscat2客户端），配置好C2域名和编码方案，由于几乎所有企业网络都放行53端口的DNS出站，木马可绕过严格的应用层防火墙
3. **木马将C2数据编码为长子域名发起TXT查询**: 后门将C2上行数据（受害主机ID、心跳、窃取数据）按字节切分，每段作为子域标签拼接成超长子域名（如`<Base32数据>.stage1.cdn-update-services.com`），向本地DNS递归服务器发起TXT或A记录查询，请求包看起来像正常的域名解析
4. **权威DNS服务器返回加密TXT记录响应**: 攻击者的权威DNS服务器接收到查询后，解析子域中的上行数据，将下行C2指令（shell命令、文件下载分片）编码后写入TXT记录返回，单次TXT响应可承载约256字节有效载荷，大数据分多次查询传输
5. **木马解码TXT记录执行指令并回传结果**: 木马从DNS响应中提取TXT记录字段，按Base32/Base64解码重组出完整指令，执行后在下一轮查询中通过子域编码回传执行结果，整个C2通信伪装成正常的DNS解析流量，网络层只看到大量53端口的UDP包

### 应用层检测

**用人话说：** DNS隧道是C2通信中最隐蔽的方式之一——攻击者把数据编码成DNS查询请求中的子域名部分发送出去。因为DNS是互联网的基础设施协议，几乎所有企业的防火墙都放行DNS流量（53端口），且很少有人会仔细检查DNS查询内容。工具如dnscat2、Iodine、Cobalt Strike的DNS Beacon都实现了这种技术。典型特征：单个客户端每秒发起数十次DNS查询，查询的子域名包含Base64编码一样的乱码字符（如"3n4kF9a2xZ8.malware.com"），而且这些域名大多解析失败（NXDOMAIN）。正常DNS查询的域名应该是有意义的完整单词。

**Sigma规则示例：**

```yaml
title: 可疑DNS隧道C2通信
status: experimental
description: 检测超长子域名DNS查询和高频TXT记录请求，可能为dnscat2/iodine DNS隧道
logsource:
    product: zeek
    service: dns
detection:
    selection_long_subdomain:
        query|re: '^[a-zA-Z0-9]{30,}\.'
    selection_txt:
        rrtype: TXT
    condition: selection_long_subdomain or selection_txt
level: medium
tags:
    - attack.t1071.004
    - attack.command_and_control
```
