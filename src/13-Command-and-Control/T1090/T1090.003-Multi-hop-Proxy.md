## 技术描述

**多跳代理**（T1090.003）是 **代理**（T1090）的一个具体变体，属于 **命令与控制** 阶段的攻击技术。

> 🔗 **打个比方**：就像在多国之间接力传递包裹——多层代理让追踪攻击者真实IP变得极其困难。

### 具体怎么理解？

攻击者使用多层代理链转发C2流量，每跳只知相邻节点

攻击者使用这种技术时，通常是在命令与控制阶段，想要达到特定的攻击目标。与父技术 T1090 相比，T1090.003 有自己独特的特点和使用场景。

### 为什么有效？

这种技术之所以有效，是因为：
1. **隐蔽性**：利用了正常系统功能或常见协议，不容易被发现
2. **技术门槛适中**：不需要特别高深的技术知识就能实施

**过渡段：** 不要误以为C2只是'发心跳包'——现代C2基础设施堪比小型互联网公司。
3. **广泛适用**：可以在多种环境和系统中使用

## 真实攻击流程

### 典型场景

攻击者在 **命令与控制** 阶段使用 多跳代理 技术，以下是典型的攻击步骤：

```mermaid
graph TD
    A["受控主机连接第一跳代理"] --> B["第一跳转发到第二跳"]
    B --> C["第二跳转发到第三跳"]
    C --> D["最终跳连接C2服务器"]
    D --> E["C2指令沿链路反向传回"]
    style D fill:#ff6b6b,stroke:#333,stroke-width:2px
```

**步骤详解：**

1. **受控主机连接第一跳代理** - 恶意载荷将流量发送到第一层代理服务器
2. **第一跳转发到第二跳** - 第一层代理解密并重新加密，转发到下一层代理
3. **第二跳转发到第三跳** - 逐层转发，每跳只知道相邻节点地址（关键步骤）
4. **最终跳连接C2服务器** - 最后一层代理将流量转发到真实C2服务器
5. **C2指令沿链路反向传回** - 攻击指令沿代理链反向传回到受控主机

## 攻击流程

```mermaid
graph LR
    A[在不同云平台租用3-5台VPS构建代理链] --> B[受控主机连接首跳代理建立加密隧道]
    B --> C[逐跳转发每跳只见相邻节点且加密密钥不同]
    C --> D[最终跳连接真实C2服务器下发指令]
    D --> E[指令沿反向链路逐跳解密重加密传回]
    
    style A fill:#4a90e2
    style E fill:#ff6b6b
```

**关键步骤说明：**

1. **在不同云平台租用3-5台VPS构建代理链**: 攻击者在AWS、阿里云、Linode、Vultr等不同云服务商分别租用位于不同国家/司法管辖区的VPS（如3跳链：香港 → 俄罗斯 → 巴拿马），每跳VPS用不同匿名身份和加密货币支付，避免单一身份关联，链路节点IP地理位置分散以增加跨境取证难度
2. **受控主机连接首跳代理建立加密隧道**: 受控主机上的Beacon仅知道首跳代理VPS地址（如香港节点），通过TLS over 443或自定义加密协议建立第一条隧道连接，首跳节点上不留存真实C2地址，即使该VPS被取证也只能定位到下一跳俄罗斯节点
3. **逐跳转发每跳只见相邻节点且加密密钥不同**: 每跳代理节点终结上一跳的加密会话后，用与下一跳协定的独立密钥重新加密转发，密钥协商通过预共享或 ephemeral Diffie-Hellman 完成，每跳VPS配置严格的`iptables`规则只允许相邻节点IP访问，链路中任何一跳被攻陷都无法解密整体流量或定位真实C2
4. **最终跳连接真实C2服务器下发指令**: 最后一跳VPS（如巴拿马节点）作为出口节点直接连接到攻击者真实C2服务器（位于自有数据中心或受控机房），出口节点保留最少日志并配置定期自毁脚本，C2服务器对受控主机的指令通过该出口节点进入代理链反向传递
5. **指令沿反向链路逐跳解密重加密传回**: 真实C2下发的指令在出口节点加密后逐跳返回，每一跳用本段密钥解密后用下段密钥重新加密继续传递，最终到达首跳节点后用与受控主机协商的密钥加密下发，整条链路使用不同协议（HTTPS→SSH→WireGuard→自定义）混合传输，规避基于流量特征的链路识别

## 缓解措施

### 优先级1：关键措施

**限制攻击面**：减少暴露的服务和端口，降低被利用的风险

```bash
# 防火墙规则示例：只允许必要的出站连接
iptables -A OUTPUT -p tcp --dport 443 -j ACCEPT  # 允许HTTPS
iptables -A OUTPUT -p tcp --dport 80 -j ACCEPT   # 允许HTTP
iptables -A OUTPUT -p tcp -j DROP                 # 阻止其他TCP
```

### 优先级2：重要措施

**加强监控**：部署EDR和SIEM系统，实时监控异常行为

### 优先级3：建议措施
