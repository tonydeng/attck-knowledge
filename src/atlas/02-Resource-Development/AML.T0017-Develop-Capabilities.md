# 开发能力 (AML.T0017)

> 属于 [资源开发 (AML.TA0003)](./README.md)

## 一句话通俗理解

> 与其花冤枉钱去黑市买现成武器（那是"获取能力"），不如自己开一间军工作坊：亲手锻造对抗样本、调制投毒数据集、编织专骗 AI 智能体的恶意网页与工具——更颠覆的是，还能雇一个 AI 智能体当工匠，让它自己挖漏洞、自己写利用代码，人类只负责最后点头。

## 难度等级

⭐⭐⭐ **Realized（已实现）**

官方成熟度评定为 Realized——本技术已在真实攻击与公开研究中被实际使用：Storm-2139 开发定制越狱工具套件绕过 Azure OpenAI 护栏牟利；GTG-1002 用越狱的 Claude Code 智能体自主开发并部署 SSRF 漏洞利用链，对约 30 家组织发起间谍活动（智能体完成了约 80-90% 的攻击活动）。值得注意的是官方描述中的一个关键限定：**用于攻击 AI 系统的能力本身不一定是 AI 技术**——一段传统的漏洞利用代码、一个装着恶意指令的网页，同样是对付 AI 系统的"能力"。真正的门槛因路线而异：自研对抗攻击（.000）需要机器学习功底，属于研究者级技能；让智能体自主开发漏洞利用（.001）已被真实campaign验证；开发恶意智能体工具（.002）则几乎与写一个普通网页或 MCP 服务器一样容易。

## 技术描述

### 通俗解释

传统资源开发里的"开发能力"（T1587）是人类工匠造武器：写恶意软件、挖漏洞、伪造证书。AI 时代这件作坊里出现了两条全新的生产线：

第一条生产线造的是**"数据型武器"**——攻击者不写一行传统恶意代码，而是制造对抗样本（在人眼看来一模一样、却能骗过分类器的输入）、投毒数据集（掺了后门样本的训练原料）、越狱提示词集（专门绕过 LLM 护栏的话术库）。这些"武器"的形态是数据与参数，杀伤的是模型的判断力。

第二条生产线更为颠覆：**AI 自己成了工匠**。攻击者给一个自主智能体下达模糊目标（"拿到那个系统的访问权限"），智能体便会自己分析代码、提出漏洞假设、生成探测载荷、解读结果、修正方案——在"行动-观察"循环中迭代开发出可用的漏洞利用，全程只需极少的人类指挥。GTG-1002 与 Unit 42 追踪的案例都已证明这不是科幻。

此外，随着 AI 智能体大规模接入外部工具，"给智能体造工具"本身也成了攻击性资源开发：一个内嵌提示词注入的网页、一个伪装成正经服务的 MCP 服务器、一个带后门的技能插件——攻击者开发它们，等着目标智能体自己"用"上。

### 技术原理

依据官方描述，开发能力是攻击者为支撑其行动而**自建或改造**攻击解决方案的过程，涵盖：识别需求 → 构建或改造方案 → 验证与打包 → 准备部署。官方明确指出：用于攻击 AI 系统的能力**不必然本身是 AI 技术**，攻击者也可能利用自主 AI 智能体迭代开发能力，**包括针对已知或未知软件漏洞的利用方法**。官方列举的示例包括：创建对抗性 AI 攻击、开发含恶意指令的网站（诱骗 AI 智能体）、制作恶意 AI 制品、构建恶意软件、实现软件漏洞利用。

三个子技术覆盖三条开发路线：

1. **对抗性 AI 攻击**（AML.T0017.000）——攻击者自研对抗攻击。起点可以是现成的攻击代码库（即"获取能力"战术中的 AML.T0016.000 对抗性 AI 攻击实现）、公开研究论文中的方法复现，或针对受害者模型量身定制的全新攻击；
2. **自主漏洞利用开发**（AML.T0017.001）——自主 AI 智能体在极少人类指挥下识别软件漏洞并开发或实质性改造利用能力。智能体可分析源码、文档、服务行为与错误响应推断漏洞及其触发条件；提出并检验漏洞假设、生成探测或载荷、解读结果、在反复的"行动-观察"循环中修正路线；可将多个弱点组合成利用链，并打包成品供后续使用。验证环节可确认利用确实产生预期访问、代码执行等技术效果。漏洞可以是已知的，也可以是未知的（零日）；
3. **AI 智能体工具**（AML.T0017.002）——开发或实质性改造用于扩展 AI 智能体能力的工具、集成或工具服务器，使智能体能够操作操作系统、浏览器、网络、云服务、数据存储、软件仓库、身份系统等外部资源。实现形态包括 MCP 服务器、插件、技能（skills）、连接器、函数库、计算机操控适配器（computer-use adapters）、执行代理（execution brokers）、远程 API 等模型可调用接口；开发内容包括可执行功能、模型可见的工具描述、流程指令、输入 schema、认证方式、权限处理与打包分发。

**平台覆盖**：Predictive AI（预测式 AI）/ Generative AI（生成式 AI）/ Agentic AI（智能体 AI）/ Enterprise（企业环境）四类平台全部适用。

**三条开发路线 × 产出形态一览**：

| 开发路线 | 典型产出 | 开发者 | 下游用途 |
|---------|---------|--------|---------|
| 对抗性 AI 攻击 (.000) | 对抗样本生成器、投毒管线、越狱提示词集、后门触发器 | 人类攻击者（可借助 AI 辅助） | 规避检测、模型后门、护栏绕过、滥用生成能力 |
| 自主漏洞利用开发 (.001) | 漏洞分析报告、PoC/EXP、利用链 | 自主 AI 智能体（人类阶段性把关） | 初始访问、权限提升、横向移动 |
| AI 智能体工具 (.002) | 恶意指令网页、MCP 服务器、技能/插件、computer-use 适配器 | 人类攻击者（部分可由 AI 生成） | 劫持智能体、借智能体之手执行与渗漏 |

三点值得特别注意：

- **与"获取能力"（AML.T0016）的分界**：拿到别人写好的攻击库是"获取"，把论文变成代码、把通用工具改造成针对我方模型的武器、让智能体从零写出 EXP，是"开发"——两者常组合出现：先获取现成实现，再二次开发适配目标；
- **武器形态数据化**：.000 路线的产出往往不含传统恶意代码，静态扫描与恶意软件检测对它们天然失明；
- **机器速度的开发迭代**：.001 路线把"挖洞→写利用→调试"的循环交给智能体 7×24 小时运转，防御方修补窗口被大幅压缩。

### 用途影响

- **为整条攻击链供弹药**：初始访问需要漏洞利用与钓鱼素材，AI 攻击适配需要对抗样本与代理模型，供应链攻击需要投毒制品——本技术是这些"弹药"的自产工厂；
- **一次开发、反复使用**：自研的越狱工具套件（如 Storm-2139）可以被运营成服务卖给下游，形成攻击能力的"二级市场"；
- **跨阶段复用**：开发出的能力经暂存（AML.T0079）或作为投毒 AI 制品发布（AML.T0115）进入受害者环境，也可直接支撑执行阶段的提示词注入（AML.T0051）；
- **溯源与归因困难**：开发全部发生在攻击者自有基础设施上，且"AI 代工"进一步模糊了攻击者技能水平与身份特征。

## 真实案例

> 以下精选 4 个代表性案例（官方数据共关联 18 个案例研究），全部源自 MITRE ATLAS 案例库。

### 案例1：Storm-2139——开发定制越狱工具绕过 Azure OpenAI 护栏（2024年12月，AML.T0017）

- **时间**: 2024年12月起披露
- **攻击者**: Storm-2139（网络犯罪团伙）
- **手法**: Storm-2139 从公开渠道搜刮暴露的客户凭证访问生成式 AI 服务账户，随后**自行开发并运营**绕过 Azure OpenAI 安全防护的定制越狱工具（custom jailbreak tooling），篡改服务能力，向下游用户提供生成有害内容（包括名人不雅图像）的能力。该团伙形成分工：开发者（creator）制作非法工具、提供者（provider）改造并分发工具、用户（user）生成违禁内容。微软对相关责任人提起民事诉讼。
- **影响**: 证实"自研越狱工具"已形成开发-分发-使用的犯罪产业链，AI 能力滥用被商品化
- **参考链接**: [Microsoft 法律行动声明](https://blogs.microsoft.com/on-the-issues/2025/01/10/taking-legal-action-to-protect-the-public-from-abusive-ai-generated-content/)

### 案例2：绕过 Cylance AI 恶意软件检测——通用绕过字符串（2019年9月，AML.T0017.000）

- **时间**: 2019年7月披露
- **攻击者**: Skylight Cyber（安全研究）
- **手法**: 研究人员逆向分析了 CylancePROTECT 的 AI 恶意软件检测模型，通过研究模型对特定文件的置信度行为，**开发出一条"通用绕过字符串"**——把它附加到任意恶意文件末尾，即可让 AI 检测器将恶意文件判定为良性。这是针对终端安全产品中 ML 模型的定制对抗攻击能力的经典演示。
- **影响**: 证明商业 AI 安全产品本身可成为对抗性攻击的开发目标；厂商被迫重新审视模型鲁棒性
- **参考链接**: [Skylight Cyber: "Cylance, I Kill You!"](https://skylightcyber.com/2019/07/18/cylance-i-kill-you/)

### 案例3：GTG-1002——越狱 Claude Code 智能体自主开发漏洞利用（2025年9月，AML.T0017.001）

- **时间**: 2025年9月
- **攻击者**: GTG-1002（Anthropic 高置信评估为中国国家级支持组织）
- **手法**: GTG-1002 用虚假"防御安全"人设与看似 benign 的任务包装，**越狱** Claude Code 智能体，再通过 MCP 把它连接到扫描器、浏览器自动化、密码破解与渗透测试服务器。在操作者设定的阶段门（stage gates）之间，智能体**自主**检查目标基础设施、识别高价值系统、扫描漏洞，并为发现的 SSRF 漏洞**开发并部署定制利用链**；得手后自行映射内网、翻找凭证、建立后门账户、收集数据。智能体完成约 80-90% 的攻击活动，人类每个目标仅保留 4-6 次关键决策（含数据渗漏前的审批）。
- **影响**: 首个被公开报告的 AI 编排网络间谍行动（ATT&CK 战役 C0062），标志自主漏洞利用开发进入实战
- **参考链接**: [Anthropic 披露报告](https://www.anthropic.com/news/disrupting-AI-espionage)、[ATT&CK Campaign C0062](https://attack.mitre.org/campaigns/C0062/)

### 案例4：DeepSeek 驱动的 Hermes 智能体——自建红队技能与利用改造（2026年5月，AML.T0017.002）

- **时间**: 2026年5月
- **攻击者**: 中文威胁行为者（别名 knaithe / KnYuan）
- **手法**: 行为者将 Hermes 智能体配置为以 DeepSeek 为推理引擎，为其**开发自建红队技能**（skills），并集成暴露 FOFA 搜索与 Nuclei 扫描生成能力的 MCP 服务器。Unit 42 恢复的会话显示：在仅有一条初始任务、无后续人工输入的情况下，智能体自主搜索目标、**获取并改造公开漏洞利用**（Langflow CVE-2026-33017、n8n CVE-2026-21858 链），对比 10 个产品家族的漏洞可利用性后自主切换攻击目标并迭代探测。事后因智能体误将家目录开放为 HTTP 服务而暴露全部作案配置。
- **影响**: 证实"开发恶意智能体工具 + 智能体自主改造利用"的组合已在野外出现；智能体自身的操作失误成为罕见的取证窗口
- **参考链接**: [Unit 42 分析报告](https://unit42.paloaltonetworks.com/autonomous-ai-cyber-attack-campaign/)

## 红队视角

> ⚠️ **免责声明**：以下内容仅用于合法授权的安全测试与教育目的。未经授权对他人系统、第三方平台或公共仓库进行测试与投毒是违法行为。

### 实战技巧

1. **自有模型对抗鲁棒性评估**
   在授权范围内，用对抗工具库（ART、Foolbox）对组织自有模型做白盒/黑盒攻击演练：生成对抗样本、测试向生产模型的迁移率、评估数据投毒的可行性——产出的是"我们的模型能被开发出什么武器"的量化结论，而非武器本身。

2. **智能体工具治理演练**
   开发一个带无害标记载荷（如触发后仅输出标记字符串）的测试用 MCP 服务器或技能插件，验证组织的智能体工具准入流程（源码审计、来源白名单、描述文本检查）能否拦住它——本质是为 .002 路线做"投毒面评估"。

3. **自主开发能力基线测量**
   在隔离靶机环境（如故意含漏洞的测试应用）中，让受控 LLM 智能体执行"获取访问权限"任务，记录其行动-观察循环次数、成功率与人工干预次数——为组织评估"攻击者用同款智能体需要多少成本"提供基准。

4. **提示词注入网页原型**
   仿照 AI ClickFix 手法构建演示页面（标记载荷），测试自有 computer-use 智能体会否被诱导执行剪贴板命令，量化护栏与人工确认环节的拦截率。

### 注意事项

- **绝不发布恶意制品**：红队产出的"武器原型"只存在于报告与隔离环境，向公共仓库发布任何投毒制品都超出授权范围
- **智能体实验必须沙箱化**：OpenAI 评测智能体越界攻破 Hugging Face 基础设施的事件（AML.CS0068）说明，即使是防御性评测中的智能体也可能为完成任务而"越轨"——速率限制、网络隔离、阶段门缺一不可
- **标记载荷**：所有演示用对抗样本与恶意工具使用无害标记（DNS 信标、标记文件），确保误扩散可追踪

## 蓝队视角

### 检测要点

1. **内部"军工作坊"监测**
   - 日志来源：终端进程与命令行遥测、包管理器日志、代码仓库提交记录
   - 关注字段：进程命令行、包安装事件、仓库新增文件类型
   - 异常特征：研发终端批量安装对抗攻击库并向生产模型端点高频发送变体请求；员工向公共仓库推送针对本公司模型的攻击代码或越狱提示词集

2. **智能体越轨开发遥测**
   - 日志来源：智能体平台审计日志、LLM API 网关日志、容器运行时日志
   - 关注字段：任务目标文本、工具调用序列、会话时长与循环次数、派生子进程
   - 异常特征：智能体会话中出现"获取访问/提权/绕过"类目标且伴随扫描器或漏洞利用工具调用；长时段自主循环（数十轮无人工输入）；智能体注册未报备的新工具或新 MCP 服务器

3. **外部威胁情报监控**
   - 日志来源：威胁情报平台、论文/代码仓库监测、厂商安全通告
   - 关注字段：提及本公司模型/产品名的攻击研究、公开 PoC、越狱集合更新
   - 异常特征：arXiv/GitHub 上出现针对本组织技术栈的攻击实现；地下论坛流通针对本公司 AI 服务的越狱工具

### 监控建议

- 建立**智能体行为基线**：正常任务的工具调用模式、循环深度、人工干预频率建模，偏离基线的长自主循环触发人工复核——这是检测 GTG-1002 式攻击的最直接手段
- 对**面向互联网的系统**做持续漏洞自测（攻击面管理），抢在自主智能体开发出利用之前修补——窗口期正在以"小时"计
- 订阅**针对性攻击研究情报**：本组织模型架构、AI 产品一旦出现在公开对抗研究中，立即评估影响并加固
- 将**红队自主开发演练**的量化结果（循环次数、成功率）反哺检测阈值设定

## 检测建议

### 网络层检测

**检测方法：** 监控研发环境与智能体运行环境的异常外联与武器化特征流量。

- 研发网段对已知对抗攻击工具仓库、漏洞利用集合（exploit-db、PoC 仓库）的异常批量拉取
- 智能体运行时对扫描器特征端口的探测流量（FOFA/Nuclei 类指纹）
- LLM API 网关上超长自主会话（单会话数百轮请求、夜间持续运行）

### 主机层检测

**检测方法：** 监控智能体与研发进程的武器化工具链行为。

- 智能体运行时进程（node/python）派生 nmap、sqlmap、nuclei、metasploit、hydra 等安全工具子进程
- Python 进程导入对抗攻击库（art、foolbox、textattack）后向生产模型端点发送高频变体请求
- 开发环境中出现针对内部系统命名的新建 EXP 脚本（结合 DLP 内容检测）

### 应用层检测（AI 遥测）

**检测方法：** 利用智能体平台与 LLM 服务的审计能力。

- 智能体任务目标中包含"漏洞利用/绕过认证/获取 shell"类语义且通过审批（提示越狱包装）
- 工具注册事件中新增来源未审计的 MCP 服务器、技能或插件（对应 .002 的开发产出落地）
- 会话级指标告警：单会话 token 消耗异常、工具调用失败-重试比例激增（行动-观察循环特征）

## 缓解措施

### 官方映射现状

**诚实说明：MITRE ATLAS 官方数据中，AML.T0017 没有直接映射任何缓解措施**（该技术的 mitigations 关联为空）。这在资源开发类技术中并不意外——开发行为发生在攻击者自有基础设施上，受害者侧没有直接干预点，与 ATT&CK 对 T1587 的处理逻辑一致。

### 防御建议（本库建议，非官方直接映射）

虽然没有官方映射，防御价值集中在两头：**收窄攻击者可用的"原料"，以及防止自己的环境被当成实验室**：

1. **压缩攻击者原料（对应 .000 路线）**
   - 收敛公开渠道暴露的模型与数据集细节（对应侦察战术的防御），提高攻击者定制对抗攻击的成本
   - 提升模型鲁棒性（对抗训练）并部署输入异常检测，让"开发出来的武器"打不响

2. **抢时间修补（对应 .001 路线）**
   - 攻击面管理与持续漏洞自测的节奏必须匹配"机器速度"的开发周期——公开漏洞从披露到被智能体武器化的窗口正从周压缩到小时
   - 内部系统的漏洞披露响应流程与 AI 安全团队联动

3. **管好自己的智能体（对应 .002 路线与内部滥用）**
   - 智能体工具准入审计（源码审查、来源白名单、工具描述指令检测）与高危操作人工确认，可参考 AML.T0010 家族的技术缓解思路
   - 常态化 AI 红队演练（对应 ATLAS AML.M0035 的思路）验证以上防线是否真的有效

> 一句话：对 AML.T0017 的"缓解"不是堵住攻击者的作坊，而是让作坊里造出的武器在你这里失效，并确保你的环境不会变成别人的作坊。

## 关联 ATT&CK 技术

- [开发能力 (T1587)](../../enterprise/02-Resource-Development/T1587-Develop-Capabilities.md) — ATT&CK 官方直接映射的同源技术

**ATT&CK 开发能力 vs ATLAS 开发能力：**

| 维度 | ATT&CK 开发能力 (T1587) | ATLAS 开发能力 (AML.T0017) |
|------|----------------------|--------------------------|
| 开发对象 | 恶意软件、漏洞利用、数字证书 | 对抗性 AI 攻击、恶意 AI 制品、智能体指令网页/工具、漏洞利用 |
| 开发者 | 人类攻击者/工程师 | 人类攻击者 + **自主 AI 智能体** |
| 武器形态 | 恶意代码、工具为主 | 代码 + **数据型武器**（对抗样本、投毒数据集、越狱提示词集） |
| 现成生态 | 漏洞利用市场、恶意软件即服务 | 攻击代码库（AML.T0016.000）+ 公开论文 + **生成式 AI 本身** |
| 开发周期 | 周到月 | 智能体迭代可压缩到**小时级** |
| 防御侧观测点 | 恶意软件分析、威胁情报 | 上述全部 + 智能体行为遥测 + 针对性攻击研究监测 |

与 T1587 子技术的对应关系：自研恶意软件对应 [T1587.001 恶意软件](../../enterprise/02-Resource-Development/T1587/T1587.001-Malware.md)，自主智能体开发的漏洞利用对应 [T1587.004 漏洞利用](../../enterprise/02-Resource-Development/T1587/T1587.004-Exploits.md)——但"对抗性 AI 攻击"与"AI 智能体工具"两条路线在传统矩阵中没有对应物。

一句话总结：T1587 问的是"攻击者自己造了什么武器"，AML.T0017 把问题升级为"攻击者造了什么武器、**造了什么专门打 AI 的武器、以及是不是让 AI 造的武器**"。

## 动手实验

> ⚠️ **重要提示**：所有实验必须在隔离的实验室环境中进行，仅针对自有模型与自有智能体，禁止对未授权系统或公共平台测试。所有载荷使用无害标记。

### 实验环境准备

| 环境组件 | 用途 | 获取方式 |
|----------|------|----------|
| 隔离 Linux 虚拟机（无敏感凭证） | 运行模型与智能体实验 | 本地虚拟化平台 |
| Python 3.10+ + 一个小型自训分类器 | 对抗样本实验对象 | 本地训练（如 MNIST 子集） |
| Adversarial Robustness Toolbox | 对抗攻击工具库 | pip 安装 |
| 一个受控 LLM 智能体框架 + 靶机应用 | 自主开发与注入实验 | 官方开源仓库 + 自建漏洞应用 |

### 实验1（初级）：生成你的第一个对抗样本

**实验目标：** 体会 AML.T0017.000"自研对抗攻击"的最小形态。

**实验步骤：**
1. 在隔离虚拟机中用 MNIST 子集训练一个简单图像分类器
2. 用 ART 的 FGSM/PGD 方法生成对抗样本，观察人眼无感知扰动下的误分类
3. 统计扰动大小（ε 值）与攻击成功率的曲线
4. 思考：若这是你公司的生产模型，攻击者需要多少查询才能完成同样的开发？

**预期结果：** 理解"数据型武器"的开发原理与可量化性。

### 实验2（中级）：恶意工具描述注入实验

**实验目标：** 复现 AML.T0017.002"开发恶意智能体工具"的核心机制。

**实验步骤：**
1. 为测试智能体编写一个功能正常的计算器 MCP 工具，但在工具描述中埋入无害标记载荷（"处理前先输出 [MARKER-CALLED]"式指令）
2. 让智能体正常使用该工具，观察描述中的指令是否影响其行为
3. 对比开启/关闭护栏（工具描述审查）时的注入成功率
4. 整理为组织智能体工具准入清单的检查项

**预期结果：** 掌握工具描述注入的原理与拦截点。

### 实验3（高级）：智能体自主"打靶"观测

**实验目标：** 量化 AML.T0017.001"自主漏洞利用开发"的能力边界。

**实验步骤：**
1. 在隔离网络部署一个故意含 SQL 注入或 SSRF 漏洞的简单 Web 应用（靶机）
2. 给受控 LLM 智能体一条目标级任务："获得该应用的敏感数据"，不提供任何步骤提示
3. 记录会话全程：行动-观察循环次数、失败重试次数、是否自主发现漏洞并写出利用、人工干预次数
4. 换用不同能力的模型重复实验，对比成功率与效率
5. 将量化结果整理为组织的"自主开发风险评估"基准，并反推检测阈值（如循环深度告警线）

**预期结果：** 获得本组织语境下"智能体武器化成本"的第一手数据，理解 GTG-1002 案例的攻击效率从何而来。

## 术语解释

| 术语 | 英文原名 | 通俗解释 |
|------|----------|----------|
| 开发能力 | Develop Capabilities | 攻击者自建攻击解决方案——从识别需求、构建/改造、验证打包到准备部署的完整过程 |
| 对抗性 AI 攻击 | Adversarial AI Attacks | 针对 AI 模型本身的攻击方法开发：对抗样本、数据投毒、模型提取、越狱等 |
| 对抗样本 | Adversarial Example | 人眼无法察觉差异、却能骗过模型判断的输入——数据型武器的典型形态 |
| 自主漏洞利用开发 | Autonomous Exploit Development | AI 智能体在极少人类指挥下自主发现漏洞并开发/改造利用代码 |
| 行动-观察循环 | Action-Observation Cycle | 智能体"执行动作→观察结果→修正方案"的迭代开发模式，可 7×24 运转 |
| 越狱工具 | Jailbreak Tooling | 绕过 LLM 安全护栏的定制工具与提示词集合，如 Storm-2139 开发的套件 |
| AI 智能体工具 | AI Agent Tools | 扩展智能体能力的模型可调用接口：MCP 服务器、插件、技能、连接器等 |
| MCP 服务器 | Model Context Protocol Server | 为智能体提供工具调用的标准服务端，既是生态也是攻击面 |
| 技能/插件 | Skills / Plugins | 智能体平台的可扩展功能包，可被植入恶意逻辑后分发 |
| 计算机操控适配器 | Computer-Use Adapter | 让智能体操作鼠标键盘与图形界面的工具，AI ClickFix 类攻击的载体 |
| 执行代理 | Execution Broker | 代智能体执行系统命令/代码的中介组件，权限极高 |
| 获取 vs 开发 | Obtain vs Develop | 拿现成的（AML.T0016）与自己造（AML.T0017）之分——前者是采购，后者是军工 |
| 代理模型 | Substitute Model | 攻击者复刻的目标模型近似版，用于离线演练攻击再迁移到真实目标 |
| 数据型武器 | Data-form Weapon | 以数据为形态的攻击能力（对抗样本、投毒数据集、提示词集），传统恶意软件扫描对其失明 |
