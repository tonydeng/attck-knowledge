## 技术描述

**AppCert DLLs**（T1546.010）是 **事件触发执行**（T1546）的一个具体变体，属于 **持久化** 阶段的攻击技术。

> 🔌 **打个比方**：就像在Windows的电源管理设置里藏了一个后门——攻击者利用AppCert DLLs机制，在特定进程启动时加载恶意DLL。

### 具体怎么理解？

注册AppCert DLL

攻击者使用这种技术时，通常是在持久化阶段，想要达到特定的攻击目标。与父技术 T1546 相比，T1546.010 有自己独特的特点和使用场景。

### 为什么有效？

这种技术之所以有效，是因为：
1. **隐蔽性**：利用了正常系统功能或常见协议，不容易被发现
2. **技术门槛适中**：不需要特别高深的技术知识就能实施

**过渡段：** 不要以为持久化就是'写个启动项'那么简单——攻击者有50种以上维持访问的方法。
3. **广泛适用**：可以在多种环境和系统中使用

## 攻击流程

```
获取Windows管理员权限 → 编写恶意AppCert DLL → 投放到System32 → 修改AppCertDLLs注册表 → CreateProcess调用触发加载
```

```mermaid
graph LR
    A["获取管理员权限"] --> B["编写恶意AppCert DLL"]
    B --> C["投放到System32"]
    C --> D["修改AppCertDLLs键值"]
    D --> E["CreateProcess触发加载"]
```

**步骤详解：**

1. **获取Windows管理员权限**
   - 通俗描述：修改AppCertDLLs注册表需要管理员权限
   - 技术细节：通过凭据窃取、漏洞利用或已有管理员账号；需对 HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\AppCertDLLs 具备写权限
   - 常用工具：Mimikatz、PsExec、UACME
2. **编写恶意AppCert DLL**
   - 通俗描述：开发符合AppCert DLL规范的恶意动态链接库
   - 技术细节：DLL必须导出 CreateProcessNotify、CreateProcessNotifyEx 等函数；Windows 在 CreateProcess 调用链中加载这些DLL并调用导出函数；与AppInit_DLLs区别在于触发机制不同
   - 常用工具：Visual Studio、MinGW、Windows SDK
3. **投放到System32目录**
   - 通俗描述：将恶意DLL放置到Windows系统目录
   - 技术细节：路径 C:\Windows\System32\appcert.dll；命名伪装系统组件（ntdll_helper.dll）；System32目录需管理员权限写入，且需绕过Windows Resource Protection (WRP) 保护
   - 常用工具：takeown、icacls、copy
4. **修改AppCertDLLs注册表键值**
   - 通俗描述：将恶意DLL文件名写入注册表项
   - 技术细节：HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\AppCertDLLs（REG_MULTI_SZ）；写入DLL文件名或完整路径；多个DLL用空格分隔；注册表项默认不存在需创建
   - 常用工具：reg add、PowerShell、regedit
5. **CreateProcess调用触发加载**
   - 通俗描述：任何调用CreateProcess API的进程启动新进程时触发恶意DLL加载
   - 技术细节：CreateProcess → 内核检查 AppCertDLLs → LoadLibrary 加载恶意DLL到调用者进程；影响所有创建子进程的程序（services.exe、svchost.exe、explorer.exe）；以调用者权限运行
   - 常用工具：系统自动加载、CreateProcess API

### 主机层检测

**Windows事件ID**：
- 事件ID 4688：进程创建（监控可疑进程）
- 事件ID 4104：PowerShell执行（监控可疑脚本）

**Linux日志**：
- /var/log/auth.log：认证日志
- /var/log/syslog：系统日志

```bash
# 检测异常进程和命令执行
grep -i "suspicious" /var/log/auth.log
```

### 应用层检测

**用人话说：** 就像在每个新生儿的出生证明上加盖一个"跟踪章"——AppCert DLLs是Windows的应用程序证书机制，注册在`HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\AppCertDlls`下的DLL会在每个进程创建时被加载到进程地址空间中。这个DLL可以挂钩进程创建相关的API函数，监控或修改每个新进程的行为。因为它是Windows证书验证机制的一部分，安全产品通常不会干扰它。攻击者利用这个特点，把自己的DLL注册进去后，系统上启动的每个进程都会执行恶意代码。
