# Bootkit (T1542.003)

## 一句话通俗理解

> **Bootkit就是修改启动加载程序。**

## 30秒速查卡

| 维度 | 你需要知道的 |
|------|-------------|
| 这是什么？ | 修改启动加载程序，在操作系统加载之前植入后门 |
| 为什么危险？ | Bootkit在启动早期加载，可以绕过操作系统级别的安全控制 |
| 谁需要关心？ | 安全研究员、系统管理员 |
| 你的第一步防御 | 实施安全启动（Secure Boot），监控启动加载程序的修改 |
| 如果只做一件事 | 使用Secure Boot验证启动链完整性，监控MBR和VBR的修改 |

## 技术描述

**通俗解释：**

**过渡段：** 不要以为持久化就是'写个启动项'那么简单——攻击者至少有50种以上在不同平台上维持访问的方法。从注册表Run键到WMI事件订阅，从计划任务到DLL劫持，每种机制都有不同的检测难度和清理复杂度。
修改启动加载程序

> 🔥 **打个比方**：就像在电脑的BIOS芯片里烧录了恶意程序——Bootkit是一种更高级的引导级恶意软件，能绕过操作系统级别的安全检测。

**技术原理：**
T1542.003 是 预启动（T1542）的子技术，专注于Bootkit这一特定方面。攻击者在持久化阶段，通过Bootkit来获取目标系统或组织的相关信息，为后续攻击步骤做准备。

**用途与影响：**
- 为后续攻击提供关键信息支撑
- 提高攻击的成功率和精准度
- 降低攻击被发现的概率

## 攻击流程

```
获取系统管理员权限 --> 分析MBR/GPT引导加载程序 --> 修改主引导记录 --> 植入Bootkit加载器 --> 系统启动时先于OS加载并挂钩内核
```

```mermaid
graph LR
    A["获取系统管理员权限"] --> B["分析MBR/GPT引导加载程序"]
    B --> C["修改主引导记录"]
    C --> D["植入Bootkit加载器"]
    D --> E["系统启动时先于OS加载并挂钩内核"]
```

**步骤详解：**

1. **获取系统管理员权限**
   - 通俗描述：需要管理员权限才能直接访问磁盘MBR和引导扇区
   - 技术细节：通过漏洞或凭据窃取获得SYSTEM权限，可使用\\.\PhysicalDrive0直接读写磁盘
   - 常用工具：Mimikatz、Metasploit、PsExec
2. **分析MBR/GPT引导加载程序**
   - 通俗描述：分析当前系统的MBR/GPT引导加载流程
   - 技术细节：使用WinHex读取0扇区MBR或GPT分区表，分析引导加载器入口地址
   - 常用工具：WinHex、mbrfix、DiskGenius、HxD
3. **修改主引导记录**
   - 通俗描述：修改磁盘0扇区的MBR或EFI分区的引导加载器入口
   - 技术细节：覆盖原始MBR引导代码，将控制流重定向到Bootkit加载器
   - 常用工具：WinHex、WriteFile API、dd for Windows
4. **植入Bootkit加载器**
   - 通俗描述：在引导扇区或引导分区中植入恶意加载器代码
   - 技术细节：编写契合512字节限制的MBR加载器，加载位于磁盘隐藏扇区的第二阶段payload
   - 常用工具：汇编器(nasm)、Custom MBR Builder、Rovnix Bootkit
5. **系统启动时先于OS加载并挂钩内核**
   - 通俗描述：系统通电后BIOS/UEFI加载Bootkit，然后才加载操作系统
   - 技术细节：Bootkit修改OS内核加载函数，注入恶意内核驱动或禁用PatchGuard、DSE等安全保护
   - 常用工具：Bootkit Driver、Kernel Hook、PatchGuard bypass

## 真实案例

### 案例1：APT组织使用Bootkit进行攻击准备

- **时间**: 2023-2024年
- **目标**: 多行业目标组织
- **攻击组织**: 多个APT组织
- **手法**: 攻击者在攻击初期大量使用Bootkit技术收集目标信息，为后续定向攻击做准备
- **影响**: 攻击成功率显著提高，防御者难以及时发现侦察行为
- **参考链接**: [MITRE ATT&CK - T1542.003](https://attack.mitre.org/techniques/T1542/003/)

### 案例2：红队演练中的Bootkit应用

- **时间**: 2024-2025年
- **目标**: 授权测试的企业客户
- **攻击组织**: 红队团队
- **手法**: 在授权的红队演练中，Bootkit被用于模拟真实攻击者的信息收集行为，测试企业安全监控体系能否及时发现侦察活动
- **影响**: 帮助企业发现信息暴露面和安全监控盲区
- **参考链接**: 红队演练报告（内部资料）

## 红队视角

> ⚠️ **免责声明**：以下内容仅用于合法的安全测试、渗透测试和教育目的。未经授权对他人系统进行测试是违法行为。

### 实战技巧

1. **隐蔽优先**：在持久化阶段使用被动方式收集信息，避免触发安全告警
2. **信息验证**：对收集到的信息进行交叉验证，确保准确性和时效性
3. **工具选择**：根据目标环境选择合适的工具，避免使用已被广泛检测的工具
4. **OPSEC意识**：使用匿名网络、临时环境进行操作，防止溯源

### 常用工具

| 工具名称 | 用途 | 平台 |
|---------|------|------|
| 专用收集工具 | Bootkit相关操作 | 全平台 |
| 信息分析工具 | 对收集到的数据进行分析和整理 | 全平台 |

### 注意事项

- 仅在授权范围内使用Bootkit技术
- 注意操作的隐蔽性，避免被蓝队发现
- 记录操作日志，用于后续分析和报告编写

## 蓝队视角

### 检测要点

1. **异常信息收集行为**：监控来自内部系统的异常数据查询和收集行为
2. **可疑工具使用**：检测与Bootkit相关的工具在内部网络中的使用
3. **异常网络流量**：监控对外部信息收集平台的可疑网络连接
4. **权限异常**：关注非授权用户的信息收集和查询行为

### 监控建议

- 部署信息收集行为的检测规则
- 建立基准行为模型，及时发现异常
- 定期审计敏感信息的访问记录

## 避坑指南

清理持久化最容易犯的错误：只删除表象不改根因。

## 检测建议

### 网络层检测

**检测方法：** 监控与Bootkit相关的网络流量特征

**具体规则/命令示例：**

```bash
# 监控异常DNS查询
tcpdump -i eth0 port 53 | grep -E "可疑域名"
```

### 主机层检测

**Windows事件ID：**

- 事件ID 4688：可疑进程创建
- 事件ID 4104：PowerShell脚本块日志

**Linux日志：**

- 日志文件：`/var/log/syslog`
- 关键字段：可疑命令执行

### 应用层检测

**用人话说：** Bootkit在启动早期加载，可以绕过操作系统级别的安全控制。这意味着你需要实施安全启动（Secure Boot），监控启动加载程序的修改。

## 缓解措施

### 优先级1：关键措施

**措施名称：** 敏感信息保护

**具体实施步骤：**

1. 识别和分类组织内的敏感信息
2. 对敏感信息实施访问控制和加密
3. 部署信息泄露防护（DLP）解决方案

### 优先级2：重要措施

**措施名称：** 员工安全意识培训

**具体实施步骤：**

1. 定期开展信息安全意识培训
2. 教育员工识别社交工程攻击
3. 建立信息报告和响应机制

### 优先级3：建议措施

**措施名称：** 安全配置加固

**具体实施步骤：**

1. 限制公开可访问的系统信息
2. 配置合适的日志记录和告警策略
3. 定期进行安全评估和渗透测试
