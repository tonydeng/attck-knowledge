## 技术描述

**PAM**（T1556.003）是 **修改认证流程**（T1556）的一个具体变体，属于 **持久化** 阶段的攻击技术。

> 📚 **打个比方**：就像在Linux/macOS的门锁里加装了一个"旁路通道"——攻击者修改PAM认证模块，用自己设定的特定密码就能绕过正常认证直接登录系统。

### 具体怎么理解？

修改Linux/macOS认证模块

攻击者使用这种技术时，通常是在持久化阶段，想要达到特定的攻击目标。与父技术 T1556 相比，T1556.003 有自己独特的特点和使用场景。

### 为什么有效？

这种技术之所以有效，是因为：
1. **隐蔽性**：利用了正常系统功能或常见协议，不容易被发现
2. **技术门槛适中**：不需要特别高深的技术知识就能实施

**过渡段：** 不要以为持久化就是'写个启动项'那么简单——攻击者有50种以上维持访问的方法。
3. **广泛适用**：可以在多种环境和系统中使用

## 攻击流程

```
获取Linux root权限 --> 定位/etc/pam.d/配置文件 --> 编译恶意PAM共享库.so --> 在PAM认证链中添加恶意模块 --> 用户SSH/登录时PAM模块记录明文密码
```

```mermaid
graph LR
    A["获取Linux root权限"] --> B["定位/etc/pam.d/配置"]
    B --> C["编译恶意PAM .so"]
    C --> D["在认证链中添加恶意模块"]
    D --> E["用户登录时记录明文密码"]
```

**步骤详解：**

1. **获取Linux root权限**
   - 通俗描述：攻击者需要root权限才能修改PAM配置和安装PAM模块
   - 技术细节：通过内核漏洞、SUID提权或已有后门获取root
   - 常用工具：DirtyPipe、DirtyCow、LinPEAS
2. **定位/etc/pam.d/配置**
   - 通俗描述：查看PAM认证配置文件了解认证流程
   - 技术细节：检查`/etc/pam.d/sshd`、`/etc/pam.d/login`、`/etc/pam.d/su`等配置，了解认证链顺序
   - 常用工具：cat、grep、ls
3. **编译恶意PAM .so**
   - 通俗描述：使用C语言编写并编译恶意PAM共享库
   - 技术细节：实现`pam_sm_authenticate`函数，在认证过程中捕获用户名密码；编译为`gcc -fPIC -shared -o malicious_pam.so malicious_pam.c -lpam`
   - 常用工具：gcc、libpam-dev、自研PAM后门源码
4. **在认证链中添加恶意模块**
   - 通俗描述：将恶意PAM模块添加到认证链最前位置
   - 技术细节：在PAM配置文件中添加`auth required malicious_pam.so`到认证链开头；将.so部署到`/lib/security/`或`/lib64/security/`
   - 常用工具：echo、sed、cp
5. **用户登录时记录明文密码**
   - 通俗描述：用户通过SSH或本地登录时，恶意PAM模块捕获明文密码
   - 技术细节：通过`pam_get_item(PAM_AUTHTOK)`获取用户输入的明文密码，写入隐藏文件或外发C2
   - 常用工具：自研密码记录模块、文件落盘+定时外传

检测 PAM 的关键是识别异常行为模式。以下是三个层面的检测方法：

### 网络层检测

**方法**：监控网络流量中的异常模式


### 主机层检测

**Windows事件ID**：
- 事件ID 4688：进程创建（监控可疑进程）
- 事件ID 4104：PowerShell执行（监控可疑脚本）

**Linux日志**：
- /var/log/auth.log：认证日志
- /var/log/syslog：系统日志

```bash
# 检测异常进程和命令执行
grep -i "suspicious" /var/log/auth.log
```

### 应用层检测

**用人话说：** PAM是Linux/macOS认证的核心机制，修改后可以添加万能密码、记录密码、绕过认证。这意味着你需要审计/etc/pam.d/目录和/lib/security/中的PAM模块。

## 缓解措施

### 优先级1：关键措施

**限制攻击面**：减少暴露的服务和端口，降低被利用的风险

```bash
# 防火墙规则示例：只允许必要的出站连接
iptables -A OUTPUT -p tcp --dport 443 -j ACCEPT  # 允许HTTPS
iptables -A OUTPUT -p tcp --dport 80 -j ACCEPT   # 允许HTTP
iptables -A OUTPUT -p tcp -j DROP                 # 阻止其他TCP
```
