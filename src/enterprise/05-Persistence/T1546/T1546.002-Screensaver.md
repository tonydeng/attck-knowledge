## 技术描述

**屏幕保护程序**（T1546.002）是 **事件触发执行**（T1546）的一个具体变体，属于 **持久化** 阶段的攻击技术。

> 🔧 **打个比方**：就像给Windows的屏幕保护程序换成了恶意程序——攻击者修改屏幕保护程序设置，屏保启动时自动执行恶意代码。

### 具体怎么理解？

替换屏幕保护程序为恶意程序

攻击者使用这种技术时，通常是在持久化阶段，想要达到特定的攻击目标。与父技术 T1546 相比，T1546.002 有自己独特的特点和使用场景。

### 为什么有效？

这种技术之所以有效，是因为：
1. **隐蔽性**：利用了正常系统功能或常见协议，不容易被发现
2. **技术门槛适中**：不需要特别高深的技术知识就能实施

**过渡段：** 不要以为持久化就是'写个启动项'那么简单——攻击者有50种以上维持访问的方法。
3. **广泛适用**：可以在多种环境和系统中使用

## 攻击流程

```
获取Windows访问权限 → 准备恶意.scr文件 → 修改SCRNSAVE.EXE注册表 → 系统空闲触发屏保 → 恶意程序自动执行
```

```mermaid
graph LR
    A["获取Windows访问权限"] --> B["准备恶意.scr文件"]
    B --> C["修改SCRNSAVE.EXE键值"]
    C --> D["系统空闲15分钟"]
    D --> E["屏保启动触发执行"]
```

**步骤详解：**

1. **获取Windows访问权限**
   - 通俗描述：攻击者获得目标系统对注册表 HKCU\Control Panel\Desktop 的写入权限
   - 技术细节：普通用户权限即可修改 HKCU 下的屏保设置；通过漏洞利用、RDP会话劫持或凭据窃取获得访问
   - 常用工具：Mimikatz、Empire、Cobalt Strike
2. **准备恶意.scr文件**
   - 通俗描述：将恶意后门程序重命名为.scr扩展名（Windows屏幕保护程序格式）
   - 技术细节：.scr本质上是PE可执行文件；可由 EXE 直接重命名；放置在 C:\Windows\System32\ 伪装系统文件，或隐藏目录规避检测
   - 常用工具：copy /b、Cobalt Strike Artifact、定制Payload
3. **修改SCRNSAVE.EXE注册表键值**
   - 通俗描述：将屏保程序路径指向恶意.scr文件
   - 技术细节：写入 HKCU\Control Panel\Desktop\SCRNSAVE.EXE = "C:\malware\evil.scr"；同时设置 ScreenSaveActive=1、ScreenSaveTimeOut=60（缩短触发时间）、ScreenSaverIsSecure=0
   - 常用工具：reg add、PowerShell Set-ItemProperty、regedit
4. **系统空闲触发屏保**
   - 通俗描述：系统在设定空闲时间后自动激活屏保程序
   - 技术细节：winlogon.exe 监控用户输入空闲时长 → 达到 ScreenSaveTimeOut 阈值 → 调用 SCRNSAVE.EXE 指定的程序；可通过模拟鼠标移动检测屏保是否生效
   - 常用工具：系统自动触发、nircmd sendmouse
5. **恶意程序自动执行**
   - 通俗描述：恶意.scr程序以当前用户权限自动启动，建立持久后门
   - 技术细节：scr以 /s 参数启动（屏保模式）；后门可检测父进程为 winlogon.exe 判断触发场景；后台C2回连或横向移动；移动鼠标可终止屏保但后门已驻留
   - 常用工具：Cobalt Strike、Empire、定制reverse shell

### 应用层检测

**用人话说：** 就像你把手机设为"空闲5分钟后自动打开抖音"——但实际打开的是间谍软件。Windows的屏幕保护程序是一个`.scr`（本质上是PE可执行文件），在注册表`HKCU\Control Panel\Desktop`的`ScreenSaveActive`和`SCRNSAVE.EXE`键值中配置。攻击者把自己的恶意程序重命名为`.scr`文件替换掉正常屏保，或者直接修改注册表中的路径。当电脑空闲指定时间后，这个恶意屏保就会以当前用户权限自动启动。因为屏保是系统正常功能，即使用户发现进程列表里有它也不会起疑心。
